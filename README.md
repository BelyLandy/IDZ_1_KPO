# Финансовый менеджер

## 1. Общая идея решения

Данный проект представляет собой консольное приложение для управления личными финансами. В рамках проекта реализован следующий функционал:

- **CRUD-операции**: Создание, редактирование и удаление банковских счетов, категорий и операций (доходов/расходов).
- **Аналитика**: 
  - Подсчет разницы между доходами и расходами за выбранный период.
  - Группировка операций по категориям.
  - Дополнительная аналитика – расчет процентного соотношения доходов и расходов.
- **Импорт/Экспорт данных**: Поддержка работы с форматами CSV, JSON и YAML для сохранения и загрузки данных.
- **Управление данными**: Возможность пересчета балансов счетов на основе суммарных операций.
- **Статистика**: Измерение времени выполнения сценариев (например, пересчёта балансов) с использованием паттерна Команда, обернутого в Декоратор.
- **DI и тестирование**: Проект использует DI-контейнер (Microsoft.Extensions.DependencyInjection) для внедрения зависимостей, а также покрыт unit-тестами с помощью xUnit (покрытие основных классов и бизнес-логики более 65%).

В функциональные требования внесены расширения (например, аналитика, импорт/экспорт в нескольких форматах), что позволяет гибко управлять финансовыми данными.

## 2. Принципы SOLID и GRASP

### SOLID

- **Single Responsibility Principle (SRP)**:  
  - *FinanceManager* отвечает только за хранение коллекций доменных объектов.  
  - *Фасады (AccountFacade, CategoryFacade, OperationFacade)* инкапсулируют бизнес-логику для работы с соответствующими сущностями.  
  - *FinanceOperations* содержит бизнес-логику (CRUD, аналитика, пересчет балансов) и не занимается UI.  
  - *UI (Menu, MenuItem, MenuManager)* отвечает исключительно за отображение и навигацию.

- **Open/Closed Principle (OCP)**:  
  - Модули, отвечающие за импорт/экспорт данных (DataExportImport и его реализации), легко расширяемы для добавления новых форматов без изменения существующего кода.

- **Liskov Substitution Principle (LSP)**:  
  - Использование интерфейсов (например, `IDataExporter`, `IDataImporter`, `ICommand`) позволяет подставлять различные реализации без нарушения корректности работы приложения.

- **Interface Segregation Principle (ISP)**:  
  - Каждый интерфейс предоставляет только необходимые методы (например, интерфейсы для экспорта/импорта не содержат лишнего функционала).

- **Dependency Inversion Principle (DIP)**:  
  - Зависимости (например, FinanceManager, фасады, операции) передаются через конструкторы, а DI-контейнер обеспечивает централизованное управление зависимостями.

### GRASP

- **Information Expert**:  
  - *FinanceManager* является экспертом по информации, поскольку содержит все данные о счетах, категориях и операциях.

- **Controller**:  
  - *FinanceOperations* выполняет роль контроллера, обрабатывая команды пользователя и вызывая соответствующие фасады для выполнения бизнес-логики.

- **High Cohesion и Low Coupling**:  
  - Каждый модуль (UI, Domain, Infrastructure) отвечает за свою конкретную область, что упрощает поддержку и расширение проекта.

## 3. Паттерны GoF

### Фасад (Facade)

- **Реализация**:  
  - Классы *AccountFacade*, *CategoryFacade* и *OperationFacade* объединяют методы CRUD для соответствующих доменных объектов.  
- **Важность**:  
  - Фасады упрощают взаимодействие с доменной моделью, скрывая сложные детали реализации и предоставляя единый интерфейс для внешнего кода.

### Команда (Command) и Декоратор (Decorator)

- **Реализация**:  
  - Интерфейс `ICommand` и классы *SimpleCommand* и *CommandTimeDecorator* используются для инкапсуляции пользовательских сценариев (например, пересчёта балансов) и измерения времени их выполнения.  
- **Важность**:  
  - Эти паттерны позволяют оборачивать бизнес-логику в объекты, что облегчает логирование, отложенное выполнение и динамическое добавление дополнительного функционала (например, тайминг).

### Шаблонный метод (Template Method)

- **Реализация**:  
  - В классе *DataExportImport* общая логика импорта/экспорта (получение пути, выбор стратегии) отделена от специфики работы с форматами (CSV, JSON, YAML).  
- **Важность**:  
  - Позволяет стандартизировать общие шаги обработки данных, оставляя форматозависимые части для конкретных реализаций.

### Фабрика (Factory)

- **Реализация**:  
  - Методы *GetExporter* и *GetImporter* в классе *DataExportImport* выбирают соответствующую реализацию в зависимости от расширения файла.  
- **Важность**:  
  - Гарантируют единообразное создание объектов (экспортёров/импортёров) и упрощают добавление поддержки новых форматов.

### Дополнительно

- **Посетитель (Visitor)** и **Прокси (Proxy)** – идеи для дальнейшего расширения проекта. Посетитель может использоваться для обхода сложных структур при экспорте данных, а Прокси – для реализации in-memory кэширования при работе с БД.

## 4. Покрытие тестами

Для обеспечения надёжности и корректности работы приложения разработаны unit-тесты с использованием xUnit. Тестами покрыто **более 65% кода**, включая:

- **Фасады**: `AccountFacade`, `CategoryFacade`, `OperationFacade` (тестирование методов создания, редактирования, удаления и обновления баланса).
- **Модуль импорта/экспорта**: `DataExportImport` (проверка выбора правильной стратегии по расширению файла).
- **Бизнес-логика**: Ключевые методы `FinanceOperations` (пересчет балансов, аналитика).

Данное покрытие позволяет обнаруживать ошибки на ранних этапах и упрощает поддержку проекта.

## 5. Использование DI-контейнера

В проекте используется DI-контейнер [Microsoft.Extensions.DependencyInjection](https://www.nuget.org/packages/Microsoft.Extensions.DependencyInjection) для внедрения зависимостей. Это обеспечивает:

- **Инверсию зависимостей (DIP)**: Все основные зависимости, такие как `FinanceManager`, фасады (`AccountFacade`, `CategoryFacade`, `OperationFacade`), `FinanceOperations`, `HelpMethods` и `DataExportImport`, передаются через конструкторы.
- **Централизованное управление зависимостями**: Регистрация сервисов в DI-контейнере позволяет легко изменять или расширять функциональность приложения без изменения потребляющих классов.
- **Упрощение тестирования**: Возможность подменять зависимости моки или фиктивными реализациями для unit-тестов.

**DI-контейнер используется в файле `Program.cs`**. Пример регистрации сервисов:

```csharp
var services = new ServiceCollection();
services.AddSingleton<FinanceManager>();
services.AddSingleton<AccountFacade>();
services.AddSingleton<CategoryFacade>();
services.AddSingleton<OperationFacade>();
services.AddSingleton<FinanceOperations>();
services.AddSingleton<HelpMethods>();
services.AddTransient<DataExportImport>();
var serviceProvider = services.BuildServiceProvider();
```

## 6. Инструкция по запуску приложения

### Требования

- **.NET 6 или выше**
- **Visual Studio 2022** (или любая другая IDE, поддерживающая .NET)
- **NuGet-пакеты:**
  - [Microsoft.Extensions.DependencyInjection](https://www.nuget.org/packages/Microsoft.Extensions.DependencyInjection)
  - [YamlDotNet](https://www.nuget.org/packages/YamlDotNet) – для работы с YAML
  - [xUnit](https://www.nuget.org/packages/xunit) – для работы с Unit тестами.

### Шаги для запуска

1. **Склонируйте репозиторий** (или скачайте проект) на вашу локальную машину.
2. **Откройте проект** в Visual Studio или в вашей IDE.
3. **Восстановите NuGet-пакеты:**
   - В Visual Studio откройте **Tools > NuGet Package Manager > Package Manager Console** и выполните команду:
     ```
     Update-Package –reinstall
     ```
   - Либо воспользуйтесь встроенной функцией восстановления пакетов.
4. **Соберите решение** (Build Solution).
5. **Запустите приложение:**
   - Если проект является консольным приложением, нажмите **F5** или выберите **Debug > Start Debugging**.
6. **Использование приложения:**
   - При запуске откроется главное меню, где можно выбирать пункты для создания, редактирования, удаления счетов, категорий, операций, а также для аналитики, импорта/экспорта данных и пересчёта балансов.
   - Вводите данные согласно подсказкам на экране. Для возврата в меню при импорте/экспорте введите «b».
7. **Запуск тестов:**
   - Для запуска xUnit-тестов откройте Test Explorer в Visual Studio и запустите все тесты.
